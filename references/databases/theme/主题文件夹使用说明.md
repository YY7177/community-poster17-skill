## 一、读取时机与使用范围

### （一）在分析用户要求时读取本说明

Skill 接收到新的海报任务后，应在分析用户要求阶段读取本说明，先了解主题分类和调用限制，再选择素材。读取应发生在筛选具体案例、制定视觉方案和生成图片之前，不能只在出图完成后将本说明用于检查。

建议执行顺序如下：

1. 阅读用户文案、附件和图片，初步识别任务内容。
2. 读取本说明，判断主题归属、素材适用范围和需要遵守的限制。
3. 阅读并列的“风格”“信息”文件夹中的使用说明，结合用户要求确定视觉表现与信息组织。
4. 按相关性读取所需子文件夹、案例记录和原图，再开展设计。

同一任务中，本说明已读取且未更新时，不必每轮修改重复读取。用户更换主题、改变传播目的，或说明文件更新时，应重新判断分类与调用方式。不要为完成一次任务而默认读取全部图片；先看分类和记录，再查看相关原图。

### （二）素材包含社区与非社区内容，按任务相关性使用

“主题”文件夹包含社区案例，也包含校园、公共机构、交通场所或其他非社区场景中的案例。文件夹名称表示内容主题，不表示其中所有素材均来自社区。

社区任务可以参考非社区案例，但需要判断受众、传播目的、服务场景和表达方式是否适合迁移。例如，校园防暑海报可以提供行动步骤的组织方法，但其中的校内地点、学生限定条件与机构名称不能直接用于社区任务。

每次调用应区分：

- **可以借鉴的内容：**主题表达、图标语义、行动步骤组织、标题与场景的对应关系。
- **需要调整的内容：**人物身份、空间背景、语气、参与方式和受众称呼。
- **不能直接沿用的内容：**案例中的事实、专属标识、真实地点及未经确认的专业结论。

素材具有参考价值不等于适合整张复用。社区与非社区属性无法判断时标记“场景待核实”，不要凭图片风格推定来源。

### （三）主题、风格、信息三个文件夹的分工与配合

三个文件夹处于同一级，共同支持出图，不将“风格”和“信息”作为“主题”的下级分类。

| 文件夹 | 主要回答的问题 | 提供的参考 |
| --- | --- | --- |
| 主题 | 海报讲什么，哪些场景与元素相关？ | 主题类别、相关案例、场景与内容表达 |
| 风格 | 海报采用什么视觉表现？ | 插画、照片、图形文字、配色与视觉调性等规则 |
| 信息 | 海报有哪些内容，怎样让居民看懂并行动？ | 主副标题、正文层级、服务信息、缺失信息处理等规则 |

Skill 在需求分析阶段综合读取三份说明，再按需查找各文件夹素材。主题案例的视觉风格不自动成为最终风格；其文字层级也不自动覆盖当前任务要求。

用户明确要求优先于默认设置。说明之间存在冲突时，先区分事实、视觉和信息组织各自负责的范围；涉及无法同时满足的用户要求时集中询问，不自行忽略其中一项。未提供某个文件夹时，使用已有规则继续可完成的工作，并在测试记录中注明缺失，不声称已读取不存在的资料。

## 二、主题分类与素材整理

### （一）六类主题：安全与应急、便民服务、出行与活动宣发、法律知识、关怀与志愿、健康与防护

以海报的核心内容和行动目标确定主分类。六个子文件夹名称应保持一致，避免使用多个近义名称保存同类素材。

| 子主题 | 主要内容 | 分类边界 |
| --- | --- | --- |
| 安全与应急 | 消防、用电、防灾、避险、应急处置与反诈提醒 | 以防止风险或指导应对为核心；系统讲解法规时归法律知识 |
| 便民服务 | 服务站开放、办事咨询、公共设施、便民办理与服务通知 | 以获得日常服务为核心；以活动参与为核心时归出行与活动宣发 |
| 出行与活动宣发 | 交通出行、路线提示、活动预告、招募、报名与现场指引 | 普通活动招募归此类；以志愿招募和公益互助为核心时归关怀与志愿 |
| 法律知识 | 法规普及、权益保护、法律咨询与维权知识 | 以法律理解、权利义务或法律服务为核心 |
| 关怀与志愿 | 邻里互助、特殊群体关怀、公益行动、志愿招募与服务 | 以关怀、互助或志愿参与为核心 |
| 健康与防护 | 防暑、季节性健康提示、健康科普与日常防护 | 以健康保护为核心；应急撤离和救援组织等归安全与应急 |

分类用于查找素材，并不要求每个主题采用固定版式、颜色或人物。表中的内容为类别示例，不是可以直接用于发布的专业指导。

### （二）跨主题素材的归类与标签规则

每个案例确定一个主分类，再用辅助标签说明其他关联主题。主分类依据“这张海报最希望受众理解或完成什么”，不要仅依据某个关键词。

例如，反诈海报以风险提醒为主时归“安全与应急”，辅以“法律知识”标签；法律条文与维权步骤为主时归“法律知识”。高温纳凉点通知以获得服务为主时归“便民服务”，辅以“健康与防护”标签。

建议辅助标签包括：关联主题、社区或非社区场景、具体场景、目标受众、传播目的。标签使用统一词表；暂不能确定时注明“待核实”，不强行归类。

同一案例尽量只保存一份原图，通过编号和标签建立跨类别关联。不要复制到多个文件夹后分别维护不同记录。确实需要新增类别时先由小组确认，不因单个案例随意增加目录。

### （三）素材收录标准与统一记录要求

收录素材应主题明确、图片可查看、主要内容可识别，并能说明借鉴价值。来源和场景应可追溯；存在缺陷的案例可以用于问题分析，但不能混入默认推荐。

| 统一记录项 | 填写要求 |
| --- | --- |
| 编号与名称 | 使用稳定唯一编号，名称概括主题和用途 |
| 主分类与辅助标签 | 一个主分类，补充关联主题、受众与传播目的 |
| 场景属性 | 社区、非社区或待核实；必要时注明校园、交通场所等 |
| 来源与原图 | 记录发布机构或作者、出处、采集日期，以及可访问的图片路径或链接 |
| 借鉴点 | 具体写明主题表达、元素或场景组织方法及作用 |
| 适用条件与限制 | 说明能用于什么任务，以及哪些部分需要调整或禁止直接套用 |
| 核对状态 | 可参考、待核实或仅问题分析，并说明原因 |

“无”表示确实不存在，“未知”表示无法判断，“待补充”表示后续需要补齐。案例为 AI 生成或本组制作时明确标注，不虚构发布来源。

不收录严重模糊、无关或无新增价值的重复素材。来源或信息未确认的素材可以暂存，但应限制调用范围，不能当作专业事实依据。

## 三、主题匹配与调用规则

### （一）从用户要求中识别主题、受众与传播目的

Skill 应提取三个基本判断：主题是什么、面向谁、希望受众理解或完成什么。同时识别使用场景、真实地点要求及用户已指定的视觉限制。

主题可从完整文案与行动要求判断，不仅靠标题关键词。传播目的可以是知识科普、行动提醒、服务告知、活动报名或公益参与。若用户只提供“做一个防暑海报”，可以确定健康与防护主题；是否含纳凉服务则需要依据实际材料，不能自行添加。

能从材料明确判断的内容直接使用，不重复询问。目的不明确且会改变内容结构时，提出一个集中问题，例如“这张海报主要介绍防暑方法，还是告知纳凉服务地点？”涉及事实缺失的处理遵循“信息”文件夹说明。

### （二）选择相关素材，区分社区与非社区案例的适用条件

先按主题定位候选，再比较传播目的、受众、场景和借鉴点。优先选择行动结构相近的案例，而不是只选名称相同或画面好看的案例。

内部最多保留三个候选，选一个主要参考；必要时补充其他案例的局部方法。查看原图后再决定是否调用，不能仅凭文件名或标签下结论。

非社区案例用于社区任务时，至少核对：受众称呼是否适合居民、服务是否真实可用、场景是否会误导地点识别、参与流程是否适合当前任务。不能把校园内部流程、商业促销条件或其他机构身份直接迁移。

测试记录保留参考编号、匹配原因与实际借鉴点。无需让用户逐个审核候选案例，但涉及真实地点识别或不明事实时应确认。

### （三）提取可借鉴内容，再结合风格与信息文件夹完成设计

从主题素材中提取与任务相关的场景、元素和表达方法，再使用当前任务的真实内容重组。不要直接替换案例标题后就当作新设计。

结合“风格”说明确定表现方式与视觉一致性，结合“信息”说明确定主副标题、正文、时间地点和行动入口的层级。三类参考冲突时，保留清楚的传播目标，并按用户要求调整表现。

例如，社区志愿活动可以借鉴校园志愿案例的公益场景，用“风格”文件夹确定插画或照片表现，再由“信息”文件夹组织居民参与条件与报名方式。校园名称、日期、校内地点和原二维码不沿用。

形成方案后生成实际海报，并检查调用是否体现在画面中。若没有合适案例，采用已有默认规则出图，记录“未匹配，使用默认方案”，不虚构参考编号。

## 四、使用限制与特殊情况

### （一）参考案例中的时间、地点等事实不得直接套用

海报事实以用户当前提供或明确确认的资料为准。旧案例中的日期、时间、地址、电话、费用、机构、活动条件、服务承诺和二维码不得直接套用。

健康、安全及法律案例中的专业内容只能作为主题参考，不能因为被收录就视为已验证。新任务需要使用相关内容时，按项目规定核实来源，未经确认的结论不得擅自加入成图。

专属标识、人物肖像和建筑照片应判断是否适合当前任务及是否获准使用。参考素材不意味着获得复用授权；需要原样使用但条件不明时先确认或选择可用替代素材。

### （二）主题不明确、跨类别或无匹配素材时的处理

| 情况 | 执行规则 |
| --- | --- |
| 主题明确但有多个关联类别 | 确定一个主分类，以标签补充其他关联主题 |
| 主题不明确，但已有足够文案 | 根据核心行动判断，并简短说明采用的判断 |
| 两种理解会导致明显不同的内容 | 集中询问传播目的，确认后再确定方案 |
| 没有匹配案例 | 使用默认方案继续，记录素材缺口，不强行套用无关案例 |
| 原图打不开或内容看不清 | 更换可查看素材；必要时请求补充，不假装已读到画面细节 |
| 用户指定与案例不同的风格 | 保留主题借鉴点，按用户指定风格表现 |

遇到新主题时可以先用“未匹配主题”记录测试，不自动修改六类目录。后续根据重复需求和素材数量决定是否新增分类。

### （三）用户提供真实社区图片时的建筑保留要求

首先区分图片是地点参考还是风格参考。用户表示“这是我们社区”“按这个建筑画”时，应作为地点参考处理；用途不明且影响方案时再询问。

作为地点参考时，应保留主要建筑轮廓、屋顶特征、入口位置、楼栋左右顺序、前后遮挡和相对高度。用户要求保留的门牌、名称或特色构件也应核对。可简化纹理与杂物，但不能把实际建筑改成通用城市景观。

主题案例不得覆盖用户提供的真实建筑。不得擅自增加楼栋、挪动主要入口或补画照片未显示的空间。名称和门牌文字使用可靠素材或文字排版，不凭生图结果猜写。

生成后对照原图检查关键锚点。明显偏差应返修；仍难以稳定保留时改用原照片裁切排版或更保守的处理方式。仅要求局部修改时保持已确认建筑与事实不变，并重新检查受影响部分。

## 五、检查与更新

### （一）检查主题匹配与素材适用性

出图前检查主分类是否围绕核心传播目标，参考素材是否适合受众和场景，社区与非社区属性是否准确记录。借鉴点应能够具体说明，而不是笼统写“参考了这个案例”。

出图后检查是否误用了旧案例事实、场景身份、机构标识或专业内容；有真实社区图片时检查建筑锚点。风格和信息可读性分别依据相应文件夹说明核对。

发现问题先修正再导出。记录区分“通过”“已修正”和“待确认”，未经检查的内容不标记通过。

### （二）验证 Skill 能否正确读取和调用

第一版测试应覆盖以下场景：

1. 一个资料完整、能够匹配主题案例的社区任务，检查读取和调用顺序。
2. 一个需要参考非社区案例的社区任务，检查是否正确调整场景且保留当前事实。
3. 一个跨主题或无匹配案例的任务，检查是否按规则分类、询问或采用默认方案。

有建筑照片的任务增加锚点检查。条件允许时，让未参与主写的组员独立操作，记录理解不清或调用失败的位置。

验证依据包括：分析需求时已读取说明；能打开所选记录和原图；能说明匹配原因；成图体现了具体借鉴方法；不会从旧案例复制事实。只找到同名文件不代表有效调用。

### （三）记录问题，补充素材并完善分类

每次测试记录任务概要、说明版本、匹配类别、参考编号、借鉴点、发现的问题、修改措施与结果。保留首稿和修改稿，用于小组讨论及汇报。

按问题更新对应资料：主题边界不清修改分类规则，场景判断不清补充标签，缺少相关案例补充素材，原图失效更新路径，调用方法不明确修改使用说明。只修改单张海报不能解决规则中的重复问题。

新增分类、字段或标签由小组确认后统一更新。保持案例编号稳定，标注版本、日期和主要变化。第一版未完成的测试标记“待验证”，不提前写成已通过成果。
