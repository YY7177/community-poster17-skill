# 当前流程：统一prompt与双模型接力（2026-10-12）

文案+图片 → 缺项集中补充（有才问） → 对话中三张风格图+三选一按钮 → 事实锁定与信息层级 → 风格化九段中英文海报prompt → Nano Banana风格场景图 → 豆包完整中文海报 → 豆包完整英文海报 → 原始图片直接交付。

默认中英文各一张、4:5，向豆包请求1200×1500。实际图片按模型返回保存，不转换格式或调整尺寸。用户最新规格优先；儿童示例的3:4不成为默认。

| 阶段 | 完成条件与记录 |
| --- | --- |
| intake / waiting_information | 原文与图片已读；只补实际关键缺项 |
| styles / waiting_style | 对话内逐张展示三张风格图片，再提供三个可点击选项；实际选定后继续，已有选择不重问 |
| prompts_ready | 已完成事实锁定、信息层级、风格语法和图文构图；prompt-plan和三个prompt文件已保存；输入事实完整进入两语prompt |
| nano_requested / nano_saved | 一次风格场景图请求及真实结果路径；无最终海报正文 |
| doubao_zh_requested / doubao_zh_saved | 中文prompt和Nano Banana结果实际提交；原始图保存 |
| doubao_en_requested / complete | 英文prompt和同一结果实际提交；原始图保存并立即交付 |
| partial / request_state_unknown | 保存已有结果和未完成语言，不自动重复请求 |

只有信息补充和风格选择是常规人工节点；不要求用户确认prompt或版式。若宿主要求外部上传授权，在首次把用户图片发送给88API或豆包前集中请求一次；风格按钮选择不替代该授权。接口需要的凭证缺失按实际接入说明处理；凭证和未知请求不以时间经过视为授权。

记录精简为实际模型、prompt与图片路径、各请求状态、输出路径，不再编写HTML布局决策、字体许可、OCR、像素QA或缩略图检查报告。`content_review: not_requested`，`postprocessing: none`。检查接口/文件是否成功是交付动作，不是对成图质量或文字的核验。

初始正常预算：一张Nano Banana风格图+中文/英文各一张豆包图，共三次付费生成。双语共用参考图；不生成多套候选，不自动付费返修。仅改一种语言时复用风格图，只请求对应语言；事实变更影响两语时同步prompt。上一请求状态不明先停止，避免重复消费。

本流程不授权GitHub发布或修改其他skill，也不改变全局模型配置。

风格选择只使用对话图片与宿主选择控件，不生成directions.html，不打开风格页面或启动服务。图片用绝对路径Markdown嵌入，先展示再调用宿主可用的 `request_user_input` 或等价三选一控件；一个问题、三个互斥选项，选项编号和图片一致，推荐项排第一并标记。无控件时用序号回复，不把默认预选视为用户确认。
